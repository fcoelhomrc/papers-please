# Test set v1 — archived 2026-09-06

The first Ragas-generated set: 400 seed chunks, 131 questions generated,
100 curated. Superseded by a rebuild, kept because these files are the only
record of what the published v1 numbers were measured against.

**Why it was replaced.** The seed pool was balanced at 80 chunks per topic,
but the curated set came out `agents` 58, `efficiency` 23, `retrieval` 13,
`evaluation` 11, `alignment` 8. Curation was even-handed across topics
(62–87% keep rate), so the 7:1 skew was introduced by Ragas at generation.
That made the headline number largely a measurement of one topic — and the
easy one, `agents` recall 0.905 against `evaluation` 0.136.

Generated by `z-ai/glm-5.3-flash` at `reasoning_effort: low`, a workaround
for reasoning consuming the entire output budget. The rebuild raises that to
medium with a matching `max_tokens`, and generates per topic with a fixed
quota so balance is structural rather than hoped for.

Measured against these files, at hybrid k=10, n=100:

```
recall=0.658±0.081  precision=0.079±0.009  hit_rate=0.780±0.082
mrr=0.606±0.085     ndcg=0.578±0.078   (precision ceiling 0.151)
```

Corresponding run output is under `eval/results/v1/` (gitignored — local only).
Chunk ids in `curated.jsonl` point at a chunks table that no longer exists;
the corpus was re-chunked to capture structural metadata, which renumbered
every row. These questions cannot be scored again without regeneration.
